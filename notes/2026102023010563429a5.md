In Mojo 1.1 `input()` reads a whole buffered chunk from stdin and returns only the first line, so with piped input (`printf 'a\nb\n' | pixi run counter`) the second call raises EOF. Interactive terminals hide this because each read returns one line. `utils/prompt.mojo get_prompt` therefore reads `FileDescriptor(0)` one byte at a time until newline, decodes with `String(from_utf8=...)`, and returns None on EOF. Keep it that way unless a future Mojo fixes input(); scripted walk runs and verification depend on it.
