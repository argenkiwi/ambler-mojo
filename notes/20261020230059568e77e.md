ambler-ts wires a walk as a map of lazily-loaded node factories and relies on structural typing (S extends NS) so a node sees only its fields. Mojo has neither trait objects (no heterogeneous map of nodes) nor structural typing, so the port uses: a `Walk` trait with `comptime State` and `step(node_id, state) -> Next[State]` implemented as an if-chain per walk; per-node `State` traits with accessor methods (the walk's State struct implements all of them, which also makes ambler-ts-style adapter nodes unnecessary); per-node `Utils` traits with a `DefaultUtils` struct and test fakes; `Node[U: Utils = DefaultUtils]` with `run[S: State]`. Node IDs stay Strings (comptime constants) so `node_not_found` mirrors the TS runtime error. Lazy loading was dropped deliberately: it existed for `import defer` start-up cost, which compiled Mojo doesn't have. Nodes are synchronous because Mojo async is unstable.
